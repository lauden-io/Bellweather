How it would work

  • Locations. One Bellweather integration, any number of locations. "+ Add location" (A) opens B to D; each location becomes its own device with its own entities, named after the location.
  • Changing a place. Every location row has a ⋮ menu with Reconfigure (A). It opens that location's own menu (E): name and place, own sensors, forecast members, stations and limits. Moving the pin uses the same map and search as adding. Nothing changes until "Save and close", which reloads Bellweather (all locations, a few seconds).
  • Shared settings. The cog on the Bellweather row (G) holds what is one decision for the whole home: how precisely services learn a location, which services are asked, and the airport archive.
  • Map and search. The map is Home Assistant's own location picker; Bellweather sends nothing while you use it. The search goes only to Open-Meteo's place search (GeoNames data), a service Bellweather already uses, so no new company learns anything. It finds towns, villages and postcodes, not street addresses; the pin then goes to the exact spot. Street addresses would need OpenStreetMap's Nominatim, whose rules (a server that can be switched without an update, attribution, at most one request per second across all users) do not fit an integration installed in many homes.
  • Limits. All six groups are on one page as sections that open with a click (F). If nothing is within a limit, the next source in line answers, as the blue box says.
  • Versions. The grey line under each menu item needs a newer Home Assistant: it exists in 2026.10, not in 2025.4; on older versions only the names show. Sub-entries, their Reconfigure and the "Add location" text work from 2025.4.
